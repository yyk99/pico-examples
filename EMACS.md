# Emacs: clangd for Pico SDK projects

clangd provides go-to-definition, find-references, completion, and diagnostics
for C/C++ via the Language Server Protocol (LSP).

## Prerequisites

1. clangd installed (`/usr/bin/clangd`)
2. `compile_commands.json` generated by CMake (see README.md)
3. Either `eglot` (built-in since Emacs 29) or `lsp-mode` (package)

## Step 1: configure clangd for cross-compilation

clangd needs to know which compiler to query for system include paths.
Without this, ARM headers are not found.

Create `.clangd` in the project root:

```yaml
CompileFlags:
  CompilationDatabase: build/pico_w
  Add:
    - --query-driver=/usr/bin/arm-none-eabi-gcc
```

Replace `build/pico_w` with your actual build directory.

## Step 2: choose an LSP client

### Option A: eglot (built-in, Emacs 29+)

Add to your Emacs config (`~/.emacs.d/init.el` or `~/.emacs`):

```elisp
(add-hook 'c-mode-hook   #'eglot-ensure)
(add-hook 'c++-mode-hook #'eglot-ensure)
```

Eglot finds clangd automatically. No further configuration needed.

Useful keybindings (active when eglot is running):

| Key | Action |
|-----|--------|
| `M-.` | Go to definition |
| `M-,` | Go back |
| `M-?` | Find references |
| `C-c C-r` | Rename symbol |
| `C-c C-a` | Code actions |
| `C-c C-d` | Show documentation |

### Option B: lsp-mode (package, more features)

Install via `M-x package-install RET lsp-mode RET` or with `use-package`:

```elisp
(use-package lsp-mode
  :commands lsp
  :hook ((c-mode   . lsp)
         (c++-mode . lsp))
  :init
  (setq lsp-keymap-prefix "C-c l"))

;; Optional: richer UI
(use-package lsp-ui
  :commands lsp-ui-mode)
```

Useful keybindings (with default `C-c l` prefix):

| Key | Action |
|-----|--------|
| `M-.` | Go to definition |
| `M-,` | Go back |
| `C-c l g r` | Find references |
| `C-c l r r` | Rename symbol |
| `C-c l a a` | Code actions |
| `C-c l h h` | Show documentation |

## Troubleshooting

**Headers not found / red underlines everywhere**

Verify `.clangd` is in the directory where you open Emacs, and that the
`CompilationDatabase` path points to a directory containing `compile_commands.json`.

Check clangd is using the right database:
```
M-x eglot-stderr-buffer      ; eglot
M-x lsp-workspace-show-log   ; lsp-mode
```

**Wrong build directory**

Update the `CompilationDatabase` path in `.clangd` and restart the LSP server:
```
M-x eglot-reconnect     ; eglot
M-x lsp-restart-workspace ; lsp-mode
```

**clangd not found**

Confirm clangd is on `exec-path`. Add to init.el if needed:
```elisp
(add-to-list 'exec-path "/usr/bin")
```
